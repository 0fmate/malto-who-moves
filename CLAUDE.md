## The task in one paragraph

For each surveillance video, output alarms `t x y class` (seconds, normalized center,
`person|vehicle|animal`): exactly one per person/vehicle/animal that **actually moves**,
and nothing for parked cars, people standing still, leaves, shadows, reflections, snow,
rain, or people inside vehicles. A cyclist is a person. Birds are not targets.
"Moving" is defined by the `moving` column of `train_tracks.csv`. See `DATA.md`.

## How the score works (drives design decisions)

- An alarm hits a target if its time is within [move start − 1 s, target leaves + 3 s] and its
  point is inside the target box at that moment, enlarged by 20% per side.
- First alarm on a target: 1.0 if the class is right, 0.6 if wrong. **Earliness is not rewarded**
  inside the window: it is fine to wait until motion is confirmed.
- Later alarms on an already-hit target are ignored (free). So track ID switches on movers are cheap.
- Any other alarm is a false alarm: weight **2** if on something that must not alarm (parked car,
  person standing still, target before it starts moving, annotated leaves/shadows), else 1.
  Every repeated alarm on a parked car counts again.
- Ambiguous cases (borderline motion, doubtful objects, unannotated areas) are neutral.
  Very small movers (`bonus`) only add points.
- Score = F1 with P = points / (hits + weighted false alarms), R = points / number of targets.

## Validation

- Test scenes are **not** in the training set: split folds by scene/source, never by frame
  or by random clip of the same scene.
- Make validation look like the test: 1–3 minute cuts, some mirrored, possibly starting
  while something is already moving.
- Every change is judged on the local CV score first; the public LB (~30% of test) is noisy.
